# Assembler passes

The assembler processes the parser's `ParseResult` through `AssemblerPipeline`:

1. `SemanticAnalysisVisitor` checks expression and operand rules and normalizes
   memory expressions into their base register, index register, and scale.
2. `SymbolLengthVisitor` collects labels, data labels, sections, and `equ` constants,
   tracks section and program offsets, and records each node's address and
   emitted length. Layout is repeated until forward symbol references settle.
   Section names are available as symbols for references such as BIOS vector
   tables.
3. `CodeGenerationVisitor` uses the completed layout and symbol table to emit
   the VM's opcode, operand metadata, register selectors, memory displacement,
   and immediate or symbol values.

Each stage receives the same `AsmContext` by reference. That context owns
assembly-wide symbols, section and program offsets, per-node layout records,
and generated bytes. Visitors keep only operation-specific state. Visitor and
expression results continue to use `std::any`: expression evaluation returns a
`uint32_t`, semantic/layout stages return `bool`, and code generation returns
`std::vector<uint8_t>`.

Run the assembler with a source path and an optional output path. Add `--list`
to print each source line followed by the bytes emitted for that line:

```text
tkyc source.asm [output.tky]
tkyc --list source.asm [output.tky]
tkyc --max 64k source.asm [output.tky]
```

`--max` (or `-m`) limits the generated image size; suffixes `b`, `k`, `m`, and
`g` mean bytes and powers of 1024. A suffix is optional and defaults to bytes.
If the image exceeds the limit, assembly fails before creating or writing the
output file. Parse and semantic errors are collected per source line; the
assembler continues checking subsequent lines and prints all collected errors
before failing.

The output is a flat byte image beginning at its first emitted address; `org`
creates zero-filled gaps between emitted addresses without allocating a prefix
from address zero. Multi-byte values are emitted most-significant byte first.
Symbols retain their absolute addresses, and operand metadata follows
`encoding.txt`. Memory expressions accept the base, index, scale, and
displacement terms in any order; only the displacement term is register-free.
Data strings encode one Unicode code point per element using the width of their
directive (`defb`, `defw`, or `defdw`) and the same most-significant-byte-first
order as numeric data. Diagnostics include the source location, source line,
and token at the reported column.
